\subsection{Version mf6.8.2---October 30, 2026}

\textbf{\underline{BUG FIXES AND OTHER CHANGES TO EXISTING FUNCTIONALITY}}
\underline{BASIC FUNCTIONALITY}
\begin{itemize}
\item Budget values with three-digit exponents were not always written to the list file with the E character (for example, 8.5159-100 instead of 8.5159E-100), which is valid Fortran but cannot be read by some post-processing tools. This occurred for absolute values between 1.0E-100 and 1.0E-99 and for values that round up to 1.0E+100. These values are now written with the E character.
\item Continuous observations written to a comma-separated value file with the DIGITS option were not written with the E character when the exponent had three digits (for example, 0.100000000000-119 instead of 0.100000000000E-119), which is valid Fortran but cannot be read by most post-processing tools. These values are now written with the E character, and every exponent is now written with three digits (for example, 0.100000000000E-004 instead of 0.100000000000E-04).
\end{itemize}

\underline{INTERNAL FLOW PACKAGES}
\begin{itemize}
\item MODFLOW 6 did not support more than one hydraulic flow barrier (HFB) on the same cell connection, but it did not report duplicates either. The saturated conductance of the connection was saved after the first barrier had already modified it, so it was never restored to its unmodified value and drifted further with each stress period, and for a confined connection the barrier correction was subtracted from the solution matrix diagonal once per duplicate. MODFLOW 6 now terminates with an error naming the two barriers and the two cells when more than one HFB is assigned to the same cell connection, in either cell order.
\item The Water Mover (MVR) Package allowed a package to be listed more than once in the PACKAGES block. The duplicate package was double-counted in the mover budget written to the listing file, which overstated the package's totals, and produced empty terms with the same names in the budget file. The program now terminates with an error when a package is listed more than once in the PACKAGES block of a model or exchange mover. Packages with the same name in different models are still allowed in an exchange mover.
\item Time-Varying Storage (TVS) PERIOD block input was silently ignored for any stress period without a corresponding Storage (STO) Package PERIOD block. TVS PERIOD blocks are now processed independently of STO PERIOD blocks. As a workaround for earlier versions, specify a STO PERIOD block for each stress period that has a TVS PERIOD block.
\item With the Newton formulation, the XT3D method scaled the flow across a horizontal connection by the saturation of the cell with the higher head, as the standard formulation does. Because the XT3D flow across a connection also depends on the heads of neighboring cells and is generally not zero when the two cell heads are equal, the residual could jump when the ordering of two nearly equal heads changed between iterations, and in one large unconfined model a single cell prevented convergence. The upstream cell is now selected from the direction of the saturated XT3D flow, which keeps the product of flow and saturation continuous. Heads computed with the Newton formulation and the XT3D option may change slightly.
\end{itemize}

\underline{STRESS PACKAGES}
\begin{itemize}
\item When the Buoyancy (BUY) Package was active, the density terms for General-Head Boundary (GHB) and River (RIV) Package boundaries used the conductance without the AUXMULTNAME multiplier, so a boundary with a multiplier other than one, including a multiplier of zero used to turn the boundary off, received a density-driven flow inconsistent with its conductance. The density terms now use the multiplied conductance.
\item With the HHFORMULATION\_RHS option of the Buoyancy (BUY) Package, part of the density term for General-Head Boundary (GHB) and River (RIV) Package boundaries was lagged on the right-hand side. Because that term scales with the head in the cell, outer iterations could cycle without converging when a river cell switched above and below the river bottom. The term only affects the diagonal of the matrix and is now always included in the matrix, so models that converged before reach the same solution.
\item When the Buoyancy (BUY) Package was active, the density correction for Drain (DRN) Package discharge ignored the AUXMULTNAME and AUXDEPTHNAME options, and the water provided to the Water Mover (MVR) Package did not include the density correction. Drain discharge is now scaled by the relative density of the discharging water in both cases.
\item When the Buoyancy (BUY) Package was active, the water that General-Head Boundary (GHB) and River (RIV) Package boundaries provided to the Water Mover (MVR) Package was calculated from the conductance and head difference only, so it did not include the density terms and differed from the boundary discharge reported in the budget. The water provided to the mover is now calculated from the full boundary discharge, including the density terms. A GHB or RIV boundary in a constant-head cell, which has no flow, also no longer provides water to the mover; previously it provided water that was not removed from the aquifer.
\end{itemize}

\underline{ADVANCED STRESS PACKAGES}
\begin{itemize}
\item A Lake (LAK) Package using the IMPLICIT option ignored the density terms of the Buoyancy (BUY) Package for every lake solved implicitly, so a model with a density contrast between a lake and the aquifer ran without a warning and returned the lake-aquifer exchange of a model without density. The program now terminates with an error when the IMPLICIT option is specified and the BUY Package is active, until the implicit formulation includes the density terms. Models that use BUY with the default LAK formulation are unaffected.
\item A Lake (LAK) Package using the IMPLICIT option reported roughly twice the outlet flow to the Water Mover (MVR) Package whenever any lake was switched to the legacy substitution solver. The mover provider term was accumulated once by the implicit formulation and again at the end of the legacy solve, so TO-MVR was about double the outlet discharge and the surplus appeared as a positive EXT-OUTFLOW, an apparent inflow that allowed the lake budget to close on the wrong flows. The mover term is now accumulated once, after the legacy-solved stages are known. Models that do not use the IMPLICIT option, or that use it without a lake on the legacy solver, are unaffected.
\item A multi-aquifer well made INACTIVE in the Multi-Aquifer Well (MAW) Package continued to conduct heat through its connections in the Multi-Aquifer Well Energy Transport (MWE) Package, because the wetted area of each connection was still calculated. An inactive well now has no wetted area, so it does not conduct heat.
\item The Unsaturated Zone Flow (UZF) Package allocated and deallocated a complete set of unsaturated-zone work arrays on every evapotranspiration calculation, and a second, smaller set on every wave-routing calculation, once per UZF cell per outer iteration per time step. The work arrays are now allocated once when the package is set up, which reduces run times by 19 to 34 percent for the UZF test problems. Results are unchanged. The wave capacity NWAV and the number of trailing waves NTRAIL are now scalars rather than arrays with one value per UZF cell, so a program that reads them through the BMI or XMI interface must be updated.
\end{itemize}

\underline{MODEL}
\begin{itemize}
\item The DISU Package now checks the ANGLDEGX values specified for horizontal connections between active cells. A warning is issued if the values for a connection and its reverse connection do not differ by 180 degrees, or, when VERTICES and CELL2D are specified, if the face normal points away from the connected cell or differs by more than 1 degree from the normal computed from the vertices shared by the two cells. The NPF Package terminates with an error if any of these conditions is not met and ANGLDEGX is required input, that is, if XT3D, K22, or SAVE\_SPECIFIC\_DISCHARGE is specified. A separate warning flags normals that deviate by more than 45 degrees from the direction between the cell centers, which is not an error but may warrant a closer look at the grid. Inconsistent ANGLDEGX values previously went undetected and could produce an invalid coefficient matrix when the XT3D option or horizontal anisotropy was active, which in some cases caused the program to terminate with a floating-point overflow in the linear solver.
\item The GWT and GWE Flow Model Interface (FMI) Packages did not recognize the GWFGRID entry in the PACKAGEDATA block and instead attempted to read the binary grid file as an advanced package budget file, causing an invalid method code error. The GWT and GWE FMI Packages now read the binary grid file, as the PRT FMI Package already did, and check that the flow and transport grids match.
\item The binary budget, head, and grid file readers stored file positions as 32-bit integers, so the Flow Model Interface (FMI) Packages for GWT, GWE, and PRT failed with an invalid method code error when reading a GWF budget or head file record located beyond 2 GiB, and failed when reading a GWF binary grid file larger than 2 GiB. File positions are now stored as 64-bit integers so that FMI can read budget, head, and binary grid files larger than 2 GiB.
\item The Streamflow Transport (SFT) Package started a time step that adaptive time stepping (ATS) repeated from the reach volume that the failed attempt ended with, rather than the reach volume at the start of the time step. Where the Streamflow Routing (SFR) Package does not route water through reach storage, the default, the solute mass of a reach whose volume changed during the time step was wrong after the repeat, although the budget still closed. The repeated time step now starts from the reach volume at the end of the previous time step.
\end{itemize}

\underline{EXCHANGES}
\begin{itemize}
\item When linking a GWE-GWE exchange to its corresponding GWF-GWF exchange, the GWF-GWF exchange was matched using only the connected node numbers, without checking that the GWF models matched those referenced by the GWE exchange. In a simulation with multiple GWF-GWF exchanges whose node lists coincide, this could link the GWE-GWE exchange to the wrong GWF-GWF exchange. The GWF model names referenced by the GWE exchange are now required to match before the node lists are compared, consistent with the GWF-GWT exchange.
\end{itemize}

\underline{SOLUTION}
\begin{itemize}
\item When a solution contained more than one GWF model, the pseudo-transient continuation (PTC) factor for steady-state Newton stress periods was calculated from the residuals of the first model in the solution, or of the first model on each process in a parallel run, divided by the cell volumes of each model. Each model now uses its own residuals. The PTC factor, and therefore the iteration history, of a multi-model steady-state Newton simulation no longer depends on the order of the models in the solution or on how the models are distributed over processes. Simulations with a single GWF model per solution are unaffected.
\end{itemize}
